# 需要登录的文件下载

普通文件返回 HTTP 401，而同一链接在已登录浏览器中能够下载时，下载请求可能缺少网站登录授权。文件类型识别和多连接下载不会自动继承浏览器的登录状态。

以下说明适用于 v0.3.6 及之后的构建；v0.3.5 安装包不包含这些授权入口。

## 使用

已有失败任务可点击右侧的「授权后重试」。新建文件下载时，也可展开「网站登录授权（可选）」。

1. 在已经登录该网站的浏览器中打开开发者工具，进入 Network（网络）。
2. 重新开始该文件的下载，选中实际文件请求。
3. 在 Request Headers（请求标头）中复制 `Cookie` 字段的值。不要复制响应中的 `Set-Cookie`。
4. 在 FFDownload 确认显示的 HTTPS 来源与该文件一致，将值粘贴到密码输入框，点击「授权并继续」。

Cookie 只需填入本机工作台，不要发送到聊天、工单或截图中。若实际下载请求没有 Cookie，或补充后仍返回 401/403，需要再检查该请求是否使用其他授权方式；当前入口只支持 Cookie。

## 保存与续传

- Cookie 只保留在当前应用进程内，不写入任务记录、下载数据库或分段恢复文件，不通过任务列表接口返回。
- 同一次运行中暂停再继续，会复用该任务的授权。删除任务、下载完成或退出服务后，不再保留对应授权。
- 重启后仍保留分段进度，但需要重新填写 Cookie 后才能继续，不会自动改为匿名下载。
- 授权仅适用于填写时的 HTTPS 来源，包括域名和端口。授权下载不跟随重定向；如源站要求跳转，请从浏览器的实际请求中获取最终文件地址。

网页 Cookie 不等于长期下载权限，其有效期和可访问内容由源站决定。当前功能不读取浏览器配置或自动导出浏览器登录信息。
