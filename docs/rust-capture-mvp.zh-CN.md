# Rust 资源捕获 MVP（仅开发模式）

自 v0.3.4 起，资源捕获和视频号代理抓包仅保留在 debug 构建中供开发验证。公开安装包和 release Web 工作台隐藏整个捕获入口，并禁用捕获启动、证书和下载接口；以下操作说明仅适用于开发模式。视频号客户端适配仍有问题，尚未作为正式功能发布。

## 实现边界

沿用 FFDownload 的 Rust 内核与界面，不 fork、不引入 res-downloader 的 Go 代码或可执行文件。参考其公开描述的“代理观察请求 → 筛选媒体 → 独立下载”原理；通过标准 Rust 网络库独立实现。

- 现有链接解析：ytdown / bbdown-core / 原生抖音、小红书、视频号适配器。
- 新增可选资源捕获：hudsucker + rcgen + rustls；只监听 127.0.0.1，默认关闭。
- 后台浏览器：Rust 启动独立 Chrome / Edge 用户目录，默认无头运行，并通过本机 CDP 尝试播放页面中的音视频。单次扫描约 30 秒，结束后关闭浏览器；需要登录、验证码或手动操作时，由用户点击“打开窗口处理”。不使用 Go、Python、Node 解析器，浏览器本身仍是用户安装的 Chromium 应用。
- 应用抓包：只在 macOS 桌面客户端提供，通过 Tauri IPC 调用 Rust 代理、证书与恢复功能。Web UI 不再提供系统代理和证书操作接口。
- 资源下载：gosh-dl / Tokio / reqwest，1–16 路、断点续传、文件校验。捕获代理不在实际下载的数据路径里。
- 视频号：现有 Rust ISAAC64 解密器。在播放详情或元数据提供对应 decodeKey 后自动解密，校验 MP4 头后发布；普通界面不再要求用户输入密钥。
- 音视频合并：原来的 FFmpeg 无转码合并能力仍保留；此次捕获 MVP 的完整单文件下载不需要它。

## 本地启动

```sh
sh scripts/start-web.sh --dev --port 17890 --download-dir ./downloads --state-dir ./.ffdm-web/capture-mvp
```

访问 <http://127.0.0.1:17890/#capture>。

1. 粘贴视频网页/分享文案，点“后台解析”。需要本机安装 Chrome 或 Edge，默认不弹浏览器窗口。
2. 等待后台浏览器加载网页并尝试播放媒体。资源出现后可直接下载，不必等扫描结束。
3. 需要登录、验证码、切换画质或手动播放时，点击“打开窗口处理”；自行完成操作后，可再次点击“后台解析”。两种模式复用本程序独立的浏览器目录，不读取日常浏览器会话。
4. “停止捕获”终止后台任务并关闭本程序启动的浏览器，已创建的下载任务独立继续。

无头模式不能替代用户完成登录或验证码，也不能保证所有自定义播放器会自动播放。只检测真实媒体响应；没有找到时明确提示打开窗口检查。

### 开发模式

```sh
sh scripts/start-web.sh --dev --port 17891 --download-dir ./downloads-dev --state-dir ./.ffdm-web/dev
```

只有 debug 构建才显示“资源捕获”“内核测速”和 Web 的“测试捕获流程”；默认启动脚本使用 release，捕获与测速入口隐藏，`/api/capture` 及其操作接口和 `/api/benchmark` 都返回 404。手工访问 `#capture` 或 `#speedtest` 会返回下载任务页，URL 或浏览器存储无法开启开发功能。桌面 release 的捕获与测速 IPC 也会拒绝执行；仅保留停止、恢复旧代理的清理能力。开发模式可用“测试捕获流程”验证真实本机 MP4 的无头捕获路径，它不是平台解析成功的证据。

普通分享页解析仍在“新建下载”中。捕获是可播放页面的补充入口，平台登录、风控、地区权限仍取决于真实播放会话。

## 小红书原始文件

“新建下载”解析小红书时，Rust 适配器优先读取笔记元数据中的 `video.consumer.originVideoKey`，检查原始文件的可读性与 MP4 文件头，再将其列为默认选项。原来只读取网页播放流，会选到压缩后带底部小红书水印的版本。原始文件直接交给 Rust 下载内核保存，不裁剪画面、不转码。

未取得可用原始文件时，保留并明确标注“网页播放版 · 可能含水印”，不会将它宣称为无水印版本。网页捕获列表仍反映播放器实际请求的资源；需要原始文件时使用笔记分享链接重新解析。作者上传的视频本身已有的文字或水印不会被修改。

用户样例验证：旧播放版为 720×1568、1,607,131 字节；平台原始文件为 882×1920、HEVC + AAC、7.477 秒、5,918,044 字节。相同时间点画面对比确认，原始文件没有旧播放版底部叠加的小红书标志与作者栏。

修复后的本地 release 服务已完成该原始文件的 4 路下载，SHA-256 与独立获取的平台原文件一致；Web UI 中“原始文件”默认选中，下载任务显示已完成。旧任务保留原来选择的版本，需要重新解析并创建任务才能切换到原始文件。

## macOS 应用抓包

在 macOS 桌面客户端进入“资源捕获”，默认显示“应用抓包”，无需把微信内容转换为网页链接。可用 `npm run desktop:dev` 运行开发客户端，或用 `npm run desktop:build` 生成本地测试包（`dist/` 下的 `.app`、DMG 和 ZIP）。本轮测试包不上传 GitHub。Windows 保留后台网页解析，系统代理自动接入仍待实现和实机验证。

1. 点击“打开证书”，在钥匙串中导入界面显示的 `FFDownload Capture <本机标识>` 证书。双击该证书，展开“信任”，将 SSL 设为“始终信任”。部分应用需要导入系统钥匙串；系统授权由用户完成。
2. 返回桌面客户端点击“刷新状态”，确认已信任；选择当前使用的网络（如 Wi-Fi）。界面会显示检测到的原 HTTP 代理。
3. 点击“开启系统代理抓包”。程序先落盘恢复记录，再设置该网络的 HTTP / HTTPS 代理，并暂时关闭 SOCKS，防止客户端绕过抓包；保留现有 HTTP 代理作为上游。认证代理、启用中的 PAC、不同的 HTTP/HTTPS 上游和纯 SOCKS 配置会提示手动处理。
4. 在微信打开视频号、小程序、公众号，或在酷狗 / QQ 音乐中重新播放。已建立的连接可能需关闭播放页甚至重启客户端后才使用新代理。
5. 回到资源列表，可按来源、音频/视频、文件大小筛选，再创建下载任务。
6. 点击“停止捕获”恢复原网络代理；“恢复原代理”也可单独恢复网络而保留本地代理监听。其他代理工具已改写的新设置不会被覆盖。异常终止时，重启同一状态目录的客户端会尝试恢复；失败时可在系统网络设置中手动恢复。

应用抓包只处理遵循系统 HTTP / HTTPS 代理的流量；它不是按进程强制重定向、VPN 或手机代理。证书固定、UDP / QUIC、非 HTTP 协议、客户端绕过代理都可能导致不可见。当前只监听本机回环地址，手机不在本轮范围内。

| 平台 / 场景 | 当前能力 | 验证状态 |
| --- | --- | --- |
| 抖音、小红书 | 网页捕获与原生链接解析；应用媒体识别 | 前一轮网页样例下载成功；应用端待验 |
| 快手 | 播放流量捕获、CDN 来源标记 | 待真实播放验证 |
| 视频号 | 稳定文件去重、播放详情适配、标题与 decodeKey 关联、Rust ISAAC64 解密 | 微信客户端端到端待验；缺少密钥不能宣称解密成功 |
| 小程序 | 任意业务域名的普通媒体响应；Referer 可见时标记“小程序” | 待真实播放验证 |
| 公众号 | 普通音视频响应；mp.weixin.qq.com 上下文归类 | 待真实播放验证 |
| 酷狗音乐、QQ 音乐 | MP3 / M4A / AAC / FLAC / WAV / Ogg / Opus / APE 识别与单文件下载 | 格式及代理路径自动测试通过；真实客户端待验 |

视频号不同客户端的播放元数据可能在应用层再次封装。0.3.1 新增独立实现的 Rust 播放页适配：只对 `channels.weixin.qq.com` 的播放页及 `res.wx.qq.com` 的 web-finder 脚本处理，保留原播放器方法的返回值与异常。少量页面桥接代码将媒体描述中的标题、媒体 URL 和解密信息传回本机代理；不读取聊天、账号或登录凭据，不注入原生微信进程，也不依赖 Go / Node / Python 解析器。

回传地址使用不在公网解析的 `.invalid` 域名、每次抓包独立的随机令牌和严格 Origin 校验；无论请求是否有效都不向上游转发。正文最多 128 KiB；页面脚本适配最多 8 MiB、15 秒，超限或解码失败保留原响应。Gzip / Brotli / Deflate 脚本可在 Rust 中解码；刷新入口脚本与模块引用以避免旧缓存绕过适配。

默认列表只展示已关联详情的视频号条目，提供“全部网络候选”筛选；候选可能来自预加载，不能称为当前播放视频。同一文件按稳定文件标识去重，保留最新可用地址，不按文件大小合并；不同清晰度保持独立。只捕获到地址时显示“等待播放详情”，不再弹出手工密钥输入框。是否能在某个微信版本命中详情方法仍需实际播放验证。普通微信媒体不再仅因 CDN 域名就被判成加密视频。

音乐播放器的试播请求只能得到试播内容。QMC / KGM / KGG / MFLAC 等已识别的专有加密文件会显示为暂不支持，不伪装为普通 MP3。

## 速度与完整性

- 普通单文件视频复用当前下载器已经计算的 SHA-256，去掉一次重复的整文件读取；重启后复用的旧轨道、合并产物和解密产物仍重新校验。
- 捕获代理不读取/缓存整个视频响应，只按响应头识别并流式转发。
- 应用模式使用独立的本机认证下载通道，CONNECT 按字节透传、无 TLS 解密；下载保持原上游网络路径，避免下载器再次经过抓包代理。停止抓包后，正在进行的下载通道保留到进程退出。代理转发不自动跟随重定向或解压，保持播放器的 Range、Cookie 与响应字节语义。
- 元数据检查仅对视频号相关 JSON 响应启用，最多同时 4 个、每个 1 MiB；超出即停止收集，转发继续。
- 下载沿用原始媒体请求的必要 Cookie、Referer、Origin、User-Agent、Authorization；不重放原来的 Range。分段由下载器重新划分，避免只拿到播放器请求的一小段。
- 内核测速使用 32 MiB 确定性数据，比较 reqwest 单流、gosh-dl 1/4/8 路；分别测试本机不限速、每响应 100 Mbps。每次都下载并校验，不复用文件内容。
- 单轮本地结果不能证明公网速度或优于 Neat。真实任务详情提供完整下载平均 Mbps / MB/s 与耗时；续传不把旧字节计入新吞吐。

## 捕获数据

每次开启新的捕获会话重置旧结果，防止网页模式和应用模式混入旧资源。系统代理状态定期核对，检测到被其他软件改写时提示处理。

资源目录最多 200 条、30 分钟有效；列表不返回 Cookie、Authorization、签名地址和解密密钥。用户选择下载后，必要请求信息进入原有私有任务存储，以便恢复下载。

代理拒绝直接访问本机控制 API 和常见私网目标。网页模式不修改系统代理；应用模式只有在用户点击开启后改写所选网络配置。程序不自动信任证书。独立浏览器使用项目内专用用户目录，不读取日常浏览器的 Cookie。

证书在状态目录 `capture-ca/` 内独立生成并跨会话复用，有效期两年。私钥和恢复记录在 Unix 上使用 0600 权限，目录使用 0700；“打开证书”只向钥匙串提供公钥证书。不再导出每次重启即变化的临时证书。停止代理不会删除用户已建立的钥匙串信任；不再使用时可按界面中的证书名在钥匙串中移除。

## 当前限制

- 仅完整音视频文件；HLS / DASH 清单和 .ts / .m4s 分片会显示但不伪装成可下载完整视频。
- 不尝试移除 DRM 或绕过付费权限。
- 捕获到的 URL 会过期；失败时回到浏览器重新播放并创建新任务。
- 捕获文件名用资源域名与资源标识生成，不宣称每个媒体响应都能关联到页面标题或清晰度。
- 当前同时维护本地 Web 与桌面模式。应用抓包已接入桌面 IPC，并提供本地 macOS 测试包；微信、音乐等真实客户端仍需人工播放验收，通过前不推送 GitHub 或发布。Windows 后台浏览器使用本机 Chrome / Edge，实际运行仍待 Windows 实机验证。
