# FFDownload v0.3.9

本版为 HTTPS 文件直链增加自定义 Header 授权下载，并修复部分 YouTube 下载在建立分段连接时立即失败的问题。

- 新建下载和失败重试支持填写 `Authorization`、`Referer`、`User-Agent`、`X-API-Key` 等 Header，可与 Cookie 一起使用。暂停或失败的文件任务也可在详情中修改授权后继续。
- 授权限定于当前 HTTPS 来源，不随重定向转发。持久化脱敏与内存授权恢复使用独立入口，Cookie 和自定义 Header 不写入任务记录或断点数据库；重启后重新填写授权即可使用原有断点。
- 修复下载内核复用已关闭的 HEAD 探测连接，以及请求阶段短暂 TLS 断线未触发重试的问题。分段 GET 继续使用连接池，重试次数仍受现有上限约束。
- 移除重复的 `Accept-Encoding: identity`，并在恢复旧任务时清理遗留的重复字段，保留原有分段进度和文件校验信息。
- macOS 与 Windows 打包脚本同时构建独立 `ffdm`，检查命令行与桌面版本一致，避免桌面更新后仍运行旧 Web/CLI。Web 侧栏、启动日志和能力接口显示实际后端版本。

授权字段格式及使用方法见 [授权下载说明](../file-download-authorization.zh-CN.md)。

## 验证

- Rust 工作区 235 项测试通过，16 项需要网络或额外环境的测试默认忽略；前端 28 项测试、Clippy 和格式检查通过。
- 本地 HTTPS 服务验证首次授权下载的单连接与四段下载、失败后替换授权和断点续传，检查服务端实际收到 Header，并扫描 SQLite、WAL 和恢复文件不包含凭据。
- release CLI 使用专用测试值通过公开 Bearer、Cookie 与 Header 回显端点的四项完整下载验证。
- macOS 客户端完成原先失败的 4K 视频下载、暂停续传和音视频合并，成品包含 3840×2160 视频与 AAC 音轨。macOS 安装包通过签名、DMG 和 ZIP 完整性校验。

以上公网结果来自测试时的可访问资源，平台访问权限和下载地址有效期仍由源站决定。Windows 安装包由 [GitHub Actions](https://github.com/gnipbao/FFDownloadManager/actions) 构建；本次本机验证环境为 Apple Silicon macOS。已发布的安装包见 [Releases](https://github.com/gnipbao/FFDownloadManager/releases)。
